# Transfer FilmCut source to Windows

The implementation was developed in a Linux cloud checkout. It does not yet
exist on the user's Windows filesystem. The target Windows directory is
`D:\FilmCut`. This transfer does not configure Codex or MCP on Windows.

## What is preserved

The Git bundle preserves the original commit plus all completed source, schemas,
services, documentation, tests, and scripts. The existing MCP implementation and
smoke test are preserved so previous work is not lost, but Windows MCP
configuration is deferred. A source-only ZIP is also supplied as a fallback.

The bundle and ZIP exclude the Linux `.venv`, Python/test caches, environment
files, local media, and generated project data. Empty `projects/`,
`assets/music/`, and `assets/sfx/` directories are preserved with `.gitkeep`.
The cloud RenderSmoke demo uses Linux source paths and is not portable project
data; equivalent synthetic footage is regenerated by the test suite.

## Safest route: clone the verified Git bundle

Download `FilmCut.bundle` and `FilmCut.bundle.sha256` from the cloud workspace
to your Windows Downloads folder. This is independent of GitHub: do not assume
the remote main branch contains the cloud implementation. No push was performed.

Open PowerShell and run:

```powershell
$ErrorActionPreference = 'Stop'
$Bundle = Join-Path $env:USERPROFILE 'Downloads\FilmCut.bundle'
$Checksum = Join-Path $env:USERPROFILE 'Downloads\FilmCut.bundle.sha256'
$Expected = ((Get-Content -LiteralPath $Checksum -Raw).Trim() -split '\s+')[0]
$Actual = (Get-FileHash -LiteralPath $Bundle -Algorithm SHA256).Hash
if ($Actual -ne $Expected) { throw 'Bundle checksum mismatch; stop.' }

$Staging = 'D:\FilmCut-transfer-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
git clone --branch work $Bundle $Staging
if ($LASTEXITCODE -ne 0) { throw 'Clone failed; original folder has not been changed.' }
git -C $Staging bundle verify $Bundle
if ($LASTEXITCODE -ne 0) { throw 'Bundle validation failed; original folder has not been changed.' }
if (Test-Path -LiteralPath 'D:\FilmCut') {
    $Backup = 'D:\FilmCut-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    if (Test-Path -LiteralPath $Backup) { throw 'Backup path already exists; stop.' }
    Move-Item -LiteralPath 'D:\FilmCut' -Destination $Backup
    Write-Host "Original Windows folder preserved at $Backup"
}
Move-Item -LiteralPath $Staging -Destination 'D:\FilmCut'
Set-Location -LiteralPath 'D:\FilmCut'
git status --short
git log -1 --oneline
Test-Path -LiteralPath '.\mcp_server.py'
```

The staging clone is fully created and bundle-verified before the original
Windows folder is moved. If any command fails, stop and inspect the named
staging/backup folders; nothing deletes your original data.

The clone's origin points to the downloaded bundle, not GitHub. Leave it this
way during transfer verification. Publishing or changing remote configuration
is a separate step. Keep the backup and downloaded bundle until validation is
complete; do not delete the original Windows files.

## Source-only ZIP fallback

Download `FilmCut-source.zip` and `FilmCut-source.zip.sha256`. Verify its hash
with `Get-FileHash` as above. Preserve `D:\FilmCut` with the same backup procedure,
then extract to the now-unused target directory:

```powershell
Expand-Archive -LiteralPath (Join-Path $env:USERPROFILE 'Downloads\FilmCut-source.zip') -DestinationPath 'D:\FilmCut'
```

ZIP contents start directly at the repository root. This restores source but
does not restore Git history. Prefer the bundle route. Do not merge the archive
over an existing folder or copy the old virtual environment into the new one.

## Recreate the environment on Windows

From `D:\FilmCut`, first check native tools:

```powershell
py -3 --version
git --version
ffmpeg -version
ffprobe -version
```

Require Python 3.11 or newer. If prerequisites are missing, install only those
needed, then open a new PowerShell session:

```powershell
winget install --exact --id Python.Python.3.12 --accept-source-agreements --accept-package-agreements
winget install --exact --id Git.Git --accept-source-agreements --accept-package-agreements
winget install --exact --id Gyan.FFmpeg --accept-source-agreements --accept-package-agreements
```

FFmpeg provides both `ffmpeg` and `ffprobe`. These are native executables, not
Python dependencies. Create a fresh Windows virtual environment and test:

```powershell
Set-Location -LiteralPath 'D:\FilmCut'
py -3 -c "import sys; assert sys.version_info >= (3,11), 'Python 3.11+ required'"
if ($LASTEXITCODE -ne 0) { throw 'Unsupported Python version; stop.' }
if (Test-Path -LiteralPath '.\.venv') { throw 'Unexpected existing environment; inspect it before proceeding.' }
py -3 -m venv .venv
if ($LASTEXITCODE -ne 0) { throw 'Virtual environment creation failed; stop.' }
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c requirements-lock.txt
if ($LASTEXITCODE -ne 0) { throw 'Dependency installation failed; stop.' }
.\.venv\Scripts\python.exe -m pip check
if ($LASTEXITCODE -ne 0) { throw 'Dependency check failed; stop.' }
.\.venv\Scripts\python.exe -m pytest -q
if ($LASTEXITCODE -ne 0) { throw 'Windows validation failed; stop.' }
```

The Linux suite has 134 tests. Three tests for foreign Windows paths on POSIX
are intentionally skipped on Windows; normal expected Windows counts are
131 passed, 3 skipped, subject to actual platform behavior. Test fixtures generate
synthetic videos; real footage is not required. No Windows success is claimed
until these commands run there.

Stop here. Do not run the Windows MCP configuration generator or edit Codex
settings during this transfer phase.
